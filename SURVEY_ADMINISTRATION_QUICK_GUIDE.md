```

  ├─ Descriptive statistics
  ├─ Hypothesis testing

  ├─ Visualization & interpretation
```

## TROUBLESHOOTING: COMMON ISSUES

### **Responder Drops Out Mid-Way**

```
✗ Problem: Participant withdraws after pre-survey
✓ Solution:
  1. Accept withdrawal gracefully
  2. Don't replace with new responder (unequal dosage)
  3. Document reason & date
  4. Proceed with unpaired analysis if >10 dropouts
  5. Report attrition in final paper
```

### **Technical Issues with S-SPARC**

```
✗ Problem: System downtime, bugs, slow load
✓ Solution:
  1. Log issue & duration
  2. Notify ALL affected users (email)
  3. Extend intervention period by duration
  4. Document in "threats to validity" section
```

### **Low Survey Response Rate**

```
✗ Problem: <70% pre-survey completion
✓ Solution:
  1. Send reminder (24h before deadline)
  2. Offer incentive (if budget allows)
  3. Extend deadline by 2-3 days
  4. Conduct follow-up calls

If still <60%: Document limitation & power analysis
```

### **Data Entry Errors**

```
✗ Problem: Typos, missing values, out-of-range scores
✓ Solution:
  1. Cross-reference with original survey
  2. Contact responder (if unclear)
  3. Use imputation for <5% missing values
  4. Exclude responder if >10% missing
```

### **Significant Dropouts in Post-Survey**

```
✗ Problem: Many didn't show up for post-survey
✓ Solution:
  1. Online post-survey option (easier)
  2. Offer multiple dates/times
  3. Send aggressive reminders (3x)
  4. Offer incentive (gift card, certificate)
```

## BEST PRACTICES FOR DATA QUALITY

### **During Survey Administration:**

✓ Quiet environment (minimal distractions)  
✓ Monitor for adequate time (don't rush)  
✓ Ask clarifying Qs if responses seem inconsistent  
✓ Check completeness before they leave  
✓ Thank & motivate for post-survey

### **During Data Entry:**

✓ Enter immediately (while fresh)  
✓ Double-entry for 10% validation  
✓ Use data validation rules (drop-downs, ranges)  
✓ Backup daily  
✓ Never modify raw data (keep copy)

### **During Analysis:**

✓ Check for data quality issues early  
✓ Document any exclusions/recoding  
✓ Run descriptive stats first  
✓ Check assumptions (normality for t-tests)  
✓ Sensitivity analysis (with/without outliers)

## CALCULATION REFERENCES (Quick Reminder)

### **Environmental Impact Metrics (from S-SPARC)**

```
Energy per query (GPT-4): ~0.0015-0.0022 Wh
Carbon (Indonesia grid): 0.384 kg CO2e / kWh
Water: ~1-5 mL per query

Example:
If user has 100 queries in 4 weeks:
- Energy: 100 × 0.002 Wh = 0.2 Wh = 0.0002 kWh
- Carbon: 0.0002 × 0.384 = 0.000077 kg = 0.077g CO2e
- If 50 queries from reuse instead of generation:
  Savings: ~0.04g CO2e
```

### **Statistical Significance**

```
p < 0.05: Statistically significant (usual threshold)
p < 0.01: Highly significant
p < 0.001: Very highly significant

Effect size (Cohen's d):
- d = 0.2 (small)
- d = 0.5 (medium)
- d = 0.8 (large)

If p < 0.05 AND d > 0.5: Both statistically & practically significant
```
