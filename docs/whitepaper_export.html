Executive Abstract

While generative artificial intelligence can generate syntactically correct code instantaneously, unconstrained student access induces severe cognitive offloading, surface-level regulation, and epistemic dependence. This research proposes an empirical, telemetry-driven framework to quantify and mitigate AI over-reliance in computer science education. We formulate the AI Over-Reliance Index (ORI), a composite metric integrating Shannon information entropy, structured problem context completeness (C-I-O-E), conceptual inquiry ratios, and keystroke-verified productive friction adherence. Operating passively within the S-SPARC and E-STRANGE platforms, the system records continuous millisecond-level interaction telemetry with zero survey overhead. A two-phase psychometric validation roadmap is executed: Phase 1 evaluates latent factor dimensionality via Exploratory Factor Analysis (EFA), while Phase 2 validates construct validity against the standardized Hou et al. (2025) scale via independent Confirmatory Factor Analysis (CFA). Methodological threats, including the maturation confound, entropy inversion paradox, NLP classifier error propagation, and Pygmalion bias, are systematically mitigated.

Keywords: AI in Education (AIED), AI Over-Reliance Index, Productive Friction, Shannon Entropy, Learning Analytics, Educational Data Mining, Software Engineering Pedagogy.

1.0 Introduction & Pedagogical Problem Formulation

The rapid integration of Generative AI into higher education has transformed computer programming labs. However, contemporary empirical literature demonstrates that effortless code generation introduces severe unintended pedagogical consequences:

The Passive Copy-Paste Feedback Loop

In unassisted environments, students frequently bypass mental decomposition by copying problem descriptions directly into commercial LLMs, copying the generated solution, and submitting it directly to automated grading platforms. This loop creates artificial success on automated unit test cases while masking foundational cognitive deficiencies that cause failure during unassisted, closed-book assessments.

Empirical Findings from Literature

  • Critical Thinking Atrophy: A systematic review confirms that over-reliance on AI dialogue systems impairs critical thinking, problem-solving, and analytical reasoning [2].
  • Weak Conceptual Transfer: Instant AI code generation exhibits near-zero correlation with independent conceptual mastery [3], [14].
  • Lower Summative Performance: Frequent dependence on LLMs correlates negatively with final course grades [4].
  • Superficial Self-Regulation: Analysis of 2,376 ChatGPT interactions proves students rarely engage in deep metacognitive reflection [5].

Pedagogical Mechanism (Cognitive Atrophy): Cognitive offloading eliminates the productive struggle of syntax tracing, edge-case debugging, and algorithmic synthesis. Without active debugging practice, learners experience rapid decay in their mental schema for computational reasoning [2], [6].

3.0 Mathematical Formulation of the AI Over-Reliance Index (ORI)

To quantify cognitive dependence in programming education, we formulate the composite AI Over-Reliance Index (ORI):

ORI = 1 - (w1 · Q_prompt + w2 · S_CIOE + w3 · R_concept + w4 · F_reflect)
Normalized Component Domain: [0, 1] • Total Weight Constraint: w1 + w2 + w3 + w4 = 1.0
Indicator 1

Q_prompt: Shannon Information Entropy (w1 = 0.30)

Defined by Claude Shannon's Information Entropy formula H(X) = -∑ p(x) log2 p(x) [11]. This component quantifies lexical richness, structural specificity, and domain-specific syntax token density within student coding queries [13], [17], penalizing generic, uninformative prompts (e.g., "fix my code").

Indicator 2

S_CIOE: Context Completeness Score (w2 = 0.25)

Evaluates the presence of four essential problem constraints: Context, Input specifications, expected Output, and Error stack trace [12]. Rewards rigorous problem framing and penalizes ambiguous queries.

Indicator 3

R_concept: Conceptual Inquiry Ratio (w3 = 0.20)

Calculated as the ratio of conceptual and logic-oriented inquiries versus requests for direct code generation (Bloom Taxonomy Levels C2-C4 vs C1), differentiating genuine cognitive inquiry from direct task outsourcing.

Indicator 4

F_reflect: Productive Friction Adherence (w4 = 0.25)

Measures adherence to the mandatory 60-second reflection pause [9] coupled with keystroke cadence verification. Dwell-time dynamics ensure authentic human typing and penalize instant copy-pasting from external LLMs.

Psychometric Rigor Disclosure: The component weights ($w_1=0.30, w_2=0.25, w_3=0.20, w_4=0.25$) represent an exploratory baseline. Structural dimensionality and final weights are empirically calibrated through Exploratory Factor Analysis (EFA) and Confirmatory Factor Analysis (CFA) across distinct student cohorts.

4.0 Core Scientific Contributions

  • Novelty 1 (Real-Time Closed-Loop Scaffolding): Unlike post-hoc taxonomies [15] or laboratory eye-tracking [16], S-SPARC computes ORI scores dynamically during active coding sessions, enabling the system to throttle AI assistance and activate Socratic hints in real time.
  • Novelty 2 (Information-Theoretic Prompt Evaluation): Adapts Shannon Information Entropy $H(X)$ [11] to quantify the technical richness, structural complexity, and domain vocabulary of programming prompts, advancing beyond naive character-count metrics [13], [17].
  • Novelty 3 (Empirical Friction & Anti Meta-Gaming): Empirically validates mandatory 60-second reflection pauses [9], [10] reinforced by keystroke dwell-time analytics to detect and prevent bypass attempts via external generative tools.
  • Novelty 4 (Closed-Loop LMS Auto-Grader Integration): Direct telemetry correlation between conversational interaction and objective unit-test outcomes on E-STRANGE (test pass rates, execution runtime, debugging iterations) and unassisted exam performance.

6.0 Research Ethics, Data Governance, & Pygmalion Safeguards

Pillar 1

Informed Consent & Opt-Out

Students receive transparent notification that aggregated interaction telemetry is analyzed for curriculum improvement, with guaranteed penalty-free opt-out options that do not affect academic grading.

Pillar 2

Cryptographic Anonymization

All personal identifiers (Student ID, Name) are cryptographically hashed into unique random research identifiers prior to analysis. Datasets are stored on secure institutional servers with strict role-based access.

Pillar 3

Pygmalion Bias Mitigation

Individual ORI scores and behavioral personas are strictly blind-masked from instructors during the semester to prevent algorithmic labeling from biasing subjective grading or student interaction.

Instructor Dashboard Harmonization: Phase-Gated Deployment

The live instructor evaluation dashboard marketed in the S-SPARC product roadmap follows a phase-gated deployment: during Phase 1 (Validation Pilot), individual metrics remain blind-masked to protect internal validity. Full live dashboard access is unlocked in Phase 2 once psychometric and construct validity are rigorously established.

7.0 Advanced Methodological Defenses & Threats to Validity

1. Reactivity & Maturation Confound Mitigation

Design: Modules 1-2 serve as an unconstrained baseline phase to record natural traits; Modules 3-4 introduce active productive friction (60s pause).
Limitation Disclosure: For a single-cohort design, maturation and friction effects are formally disclosed as a limitation; if parallel sections are available, counterbalancing (A-B vs B-A) is implemented.

2. Two-Phase Psychometric Validation Roadmap

Phase 1 (Semester 1 / Cohort 1, $N=35-50$): Instrument development and Exploratory Factor Analysis (EFA) to discover latent factor loadings across the 4 ORI indicators.
Phase 2 (Semester 2 / Cohort 2, $N \ge 80$): Independent Confirmatory Factor Analysis (CFA) to verify construct unidimensionality and prevent model overfitting.

3. Entropy Inversion Paradox (Interaction Modeling)

Paradox: Expert programmers often write concise, highly focused prompts (low raw entropy), whereas struggling novices write rambling queries.
Mitigation: Formulates an Entropy $\times$ Baseline Prior Ability (pre-test / GPA) interaction term to ensure expert prompt conciseness is not misclassified as novice over-reliance.

4. NLP Classifier Sub-Study Validation ($R_{\text{concept}}$)

Risk: Classification error in intent detection propagates into the final ORI composite score.
Protocol: Intent classification is validated against $\ge 100$ expert-annotated prompts by 2 independent human raters, requiring Cohen's Kappa $\kappa \ge 0.80$ before formula deployment.

8.0 Statistical Integrity, Anti-Circularity Protocol, & Open Science

  • Anti-Circularity Cross-Validation: Regression weights are calibrated exclusively on training folds and tested on held-out validation folds using a 5-Fold Cross-Validation protocol.
  • Standardized Convergent Validation: ORI composite scores are cross-validated against the internationally validated GenAI Reliance Scale (Hou et al., Computers & Education 2025 [1]).
  • Multicollinearity Diagnostics: All ORI predictor variables are evaluated for multicollinearity, requiring Variance Inflation Factor ($\text{VIF} < 5.0$) to guarantee component orthogonality.
  • OSF Pre-Registration: The confirmatory analysis plan is pre-registered on the Open Science Framework (OSF.io) prior to data collection to eliminate p-hacking.

9.0 Secondary Exploratory Hypotheses (Bonferroni Adjusted α = 0.0125)

H1: Green AI Paradox

Over-reliant students generate higher cumulative carbon emissions due to excessive prompt iteration volumes rather than per-query complexity (controlled for Module Fixed-Effects and semantic cache hits).

H2: AST Code Distance

Autonomous students exhibit significantly larger Abstract Syntax Tree (AST) structural distances between AI suggestions and final submissions (evaluated against the final session AI suggestion).

H3: Reflexive Pause Efficacy

Active adherence to reflection pauses positively predicts first-attempt pass rates on programming assignments (controlling for baseline prior ability as a covariate).

H4: Query Novelty & Cache Lifecycle

Semantic cache misses reflect deeper student exploratory inquiry into complex edge cases (controlled for cache maturity lifecycle to eliminate cold-start artifacts).
