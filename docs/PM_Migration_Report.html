S-SPARC System Migration & Enhancement Report

Date: August 2, 2026 Subject: Final Status of FastAPI Backend Migration & AI Chatbot Capability Enhancements

1. Background & Rationale for Migration

Previously, the S-SPARC system utilized a monolithic architecture with a Flask-based backend consolidated into a single large file (app.py, spanning thousands of lines). As the project expanded, this architecture presented several critical issues: 1. Scalability and Maintainability: The excessively long and non-modular codebase made the system difficult to manage and highly susceptible to bugs when introducing new features. 2. Concurrency Limitations: The synchronous Flask framework struggled to handle heavy queues of prolonged AI requests, frequently causing GPT requests to time out or fail mid-process. 3. AI Limitations (Statelessness): The former S-SPARC chatbot was one-directional (lacked memory). The AI could not answer follow-up questions because it immediately forgot the context of previous conversations.

Consequently, a decision was made to migrate the backend from Flask to FastAPI and to completely overhaul the AI engine to be significantly smarter and context-aware.

2. Scope of Migration and Enhancements

The migration and enhancement processes were focused on logic decoupling, asynchronous performance improvements, and building a robust AI framework:

  • Migration to a Modular Architecture (FastAPI):
  • Auth (auth.py): A dedicated module handling login, registration, and cookie-based session management, ensuring 100% compatibility with the existing PHP frontend.
  • Domain & Gamification (domain.py): A specialized module serving course data, assessments, and leaderboard points.
  • Admin (admin.py): Secure routing for fetching environmental metrics and logs (strictly restricted to administrators).

  • AI Chat (ai_chat.py): The core router for receiving user prompts and queuing them to the ChatGPT system.

  • Backend Infrastructure Upgrades:

  • Integrated Redis Queue (RQ) as an isolated background task worker. This guarantees that heavy queries to OpenAI are executed safely and will never cause the web server to block or experience long queues.

  • AI Chatbot Intelligence Enhancements (Advanced Phase):

  • Context-Aware Memory: Developed the chat_history.py service, which automatically stores and retrieves the user's last 5 conversational turns based on their active assessment. This allows the AI to correctly respond to follow-up instructions (e.g., "give me another example").
  • Custom AI Gateway (LiteLLM): Consolidated all model calls into a single centralized point. This makes it incredibly easy to swap or rotate language models in the future if a specific provider experiences downtime.
  • Hybrid Search Engine: Combined sentence-based semantic search (Dense / SentenceTransformers) with keyword-based search (Sparse / BM25) using the Reciprocal Rank Fusion (RRF) algorithm to guarantee highly relevant code context retrieval.
  • Centralized Prompt Registry: Centralized all system prompts within prompts.py to ensure the bot's language and persona remain consistent (educational and primarily Indonesian-speaking).

Conclusion

The migration from Flask to FastAPI is 100% Complete and Successful. The current architecture is far more robust, modular, and fully prepared to handle larger traffic loads through its asynchronous capabilities (Redis/RQ). Furthermore, the S-SPARC chatbot has evolved from a mere "stateless generator" into a "smart conversational assistant" capable of remembering the learning context of every individual student.

No drastic overhauls were required on the frontend UI, as cross-session compatibility (SessionMiddleware) between the new backend and PHP was mapped and preserved flawlessly.
